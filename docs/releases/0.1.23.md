# TensorCore 0.1.23 release notes

TensorCore 0.1.23 is the first release candidate qualified as a
cross-platform native SDK rather than only an Apple-focused kernel preview.
It keeps Metal as the flagship backend while closing the public ABI,
portable-CPU, Windows, CUDA, packaging, and evidence contracts needed by
downstream consumers.

This document distinguishes three states deliberately:

- **Release-qualified** means the implementation built and executed on
  representative physical hardware with clean-revision evidence.
- **Implemented, not qualified** means source and tests exist, but this
  release does not claim runtime support without the required hardware proof.
- **Unsupported** means the release rejects or excludes the configuration
  instead of silently falling back and claiming success.

## Highlights

- DiLoCo state serialization now defaults to the SHA-256-protected ABI v2
  format while retaining byte-identical, explicitly requested ABI v1 output.
- `tc_diloco_capability_query` provides size-versioned, fail-closed discovery
  of state, optimizer, compression, and wire-format support.
- Python, Rust, Swift, WebAssembly, PyTorch, native exports, and public
  constants agree on the current ABI and capability bits.
- Public C enum boundaries reject invalid integral representations without
  invoking C++ undefined behavior.
- CUDA defaults are toolkit-aware from CUDA 11.4 through CUDA 13 and include
  native Jetson `sm_72` and Blackwell `sm_120` images where supported.
- Windows MSVC now compiles all backend-independent geometry and quantum
  tests without POSIX-only variable-length arrays or math constants.
- Evidence checkers bind runtime results to an exact clean source revision and
  reject missing status fields, stale provenance, backend fallback, or absent
  required kernels.
- Release and CI workflows now reject tracked private home paths, private
  network addresses, account-qualified internal hosts, and live cloud-instance
  identifiers.
- Public release receipts now use logical path labels and platform classes;
  Windows evidence no longer records usernames, machine names, checkout paths,
  or clone URLs.
- The ICC architecture model machine-checks ABI parity, backend dependencies,
  state-version authority, transport authentication, and release privacy.

## Public ABI changes

### DiLoCo capability discovery

`tc_diloco_capability_query` reports what the linked runtime can actually
serialize and transmit. Its output structure begins with `struct_size` and
`abi_version`, supports older minimum-size callers, leaves a newer caller's
unknown tail untouched, and rejects unknown ABI versions without mutating the
output.

Consumers should query this API instead of inferring behavior from a package
version or symbol-presence check.

### State ABI v2

The current DiLoCo state format uses a 64-byte header:

```text
  0  magic "TCDLSTA2"          32  SHA-256(payload)
  8  u32 abi_version = 2       64  payload
 12  u32 header_size = 64
 16  u64 total_size
 24  u64 payload_size
```

The payload remains deterministic and shares its logical layout with v1.
Callers that must interoperate with a v1 peer can request
`TC_DILOCO_STATE_ABI_VERSION_1` explicitly. Deserialization verifies sizes,
digest, enum values, and complete input before committing restored state.

### Runtime capabilities

The append-only runtime capability mask adds:

- `TC_CAPABILITY_DILOCO_CAPABILITY_QUERY`
- `TC_CAPABILITY_DILOCO_STATE_ABI_V2`

Unknown mask bits and unavailable backends remain fail-closed.

## Backend and runtime changes

### Metal

- Family policy remains Apple7 through Apple10 with Apple11 reserved.
- BF16 is native only where the detected family reports it; older families
  use the documented fallback.
- M5 TensorOps remain separately SDK- and hardware-gated. Compiling the source
  is not accepted as physical M5 runtime evidence.

### CUDA

- CUDA 11.4 defaults to `sm_70`, `sm_72`, `sm_75`, `sm_80`, and `sm_86`,
  with forward PTX at the newest supported target.
- CUDA 11.8 adds Ada and Hopper targets.
- CUDA 12.8 adds Blackwell `sm_100` and `sm_120`.
- CUDA 13 removes unsupported pre-Turing targets while retaining native
  Blackwell images.
- CUDA device enumeration now distinguishes an unavailable runtime/device
  from an invalid device index.
- Runtime smoke evidence requires actual CUDA dispatch for every applicable
  GEMM/training operation. A portable-CPU fallback is a failure.

### Portable CPU and Windows

- The native SDK builds without Metal, CUDA, or HIP on macOS, Linux, and
  Windows.
- Installed CMake, pkg-config, C, and C++ consumer contracts remain
  relocatable.
- Windows uses Visual Studio Build Tools/MSVC and produces a DLL, import
  library, static library, headers, CMake config, and pkg-config metadata.
- Python smoke validates the installed DLL rather than only importing the
  source tree.

## Language bindings and packages

The following surfaces are versioned at 0.1.23 and checked against the same
public C ABI:

- Python ctypes package and Apple wheel
- Rust FFI crate
- Swift package
- WebAssembly wrapper
- PyTorch dispatcher/autograd extension
- Eshkol bridge
- Native C/C++ CMake and pkg-config consumers

The GitHub release contains:

- `tensorcore_apple-0.1.23-...whl`
- macOS native SDK `.tar.gz`
- Linux native SDK `.tar.gz`
- Windows native SDK `.zip`
- `SHA256SUMS`

The Python wheel remains Apple/Metal-specific. Linux and Windows are native
SDK distributions in this release.

NumPy remains optional at runtime and is exposed through the `test` extra for
contributors and release correctness smoke:

```sh
python3 -m pip install 'tensorcore-apple[test]'
```

## Upgrade guidance

### From 0.1.22

No existing public symbol is removed or renamed. Rebuild downstream native
consumers so they receive the current headers and capability constants.

If a consumer persisted DiLoCo blobs without specifying a version, new blobs
will use v2. Existing v1 blobs continue to deserialize. To keep emitting v1,
pass `TC_DILOCO_STATE_ABI_VERSION_1` explicitly.

Replace package-version feature tests with `tc_diloco_capability_query` and
`tc_runtime_capabilities_get`.

### Clean install

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
ctest --test-dir build --output-on-failure -j4
cmake --install build --prefix /opt/tensorcore
```

Downstream CMake:

```cmake
find_package(tensorcore CONFIG REQUIRED)
target_link_libraries(my_app PRIVATE tensorcore::tensorcore_shared)
```

## Known limitations

- Physical M5/Metal 4 execution is not qualified in 0.1.23.
- HIP/chipStar runtime support is not qualified in 0.1.23.
- NVIDIA Ampere is compiled by the architecture policy but lacks a qualifying
  release receipt for this version.
- Windows CUDA is not included in the supported matrix.
- `TC_DILOCO_COMPRESS_FP16` is accepted but currently uses dense FP32 on the
  wire; capability discovery reports that physical representation honestly.
- DiLoCo dropout-tolerance policy is declared but not implemented.
- The Apple wheel is unsigned and not notarized.

## Verification and publication policy

Before tagging, run:

```sh
scripts/check_version_consistency.sh
python3 scripts/check_release_privacy_selftest.py
python3 scripts/check_release_privacy.py
python3 scripts/check_release_privacy.py --history
python3 scripts/check_release_artifact_privacy_selftest.py
python3 scripts/check_docs_links.py
python3 scripts/check_full_capability_campaign.py
scripts/run_release_sanitizer_evidence.sh
python3 scripts/run_release_verification_evidence.py
```

The final release-candidate join additionally requires exact-revision M2,
Windows CPU, Jetson, and Blackwell receipts. It emits the six ICC finish-gate
events only after all inputs match the same clean commit; stale hardware
evidence is a failure.

The complete platform, sanitizer, binding, package, evidence, and publication
runbook is [release_process.md](../release_process.md). Privacy requirements
are normative and documented in [release_privacy.md](../release_privacy.md).

## Security

Release artifacts contain no machine-specific absolute home directories,
private network coordinates, account-qualified internal SSH targets, private
repository coordinates, or live cloud-instance identifiers. The release
workflow enforces that rule against every tracked text file before building or
publishing artifacts.

Security vulnerabilities should be reported using [SECURITY.md](../../SECURITY.md),
not in a public issue containing exploit details.
